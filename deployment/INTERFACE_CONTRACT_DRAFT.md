# 客户端同步 TLQ 接口契约草案 v0.3

本次仅更新文档，不修改实现、不部署或调用 AWS。本文的“已确认”与“待确认”分开标记，待确认建议不视为最终规则。

## 已确认

- 数据库计划为 Aurora MySQL，区域 us-east-2；实例规格和引擎版本待确认，不执行 PostgreSQL 方案。
- 沿用现有 Transform 的 75 字段字符串 JSON 契约；Load 请求体为 JSON 数组。
- 完整保留 CSV 中的重复记录，不按 Record_ID 去重，不将 Record_ID 设为唯一键。
- Load 每次直接 INSERT，保留 run_id 隔离不同实验；不执行去重、UPSERT 或覆盖写入。
- 暂不实现 load_batches、内容哈希或批次重试幂等；此前以 (run_id, batch_id) 防重的设计不再适用于当前版本。
- 每批使用独立事务，整批成功才提交；事务失败整体回滚，不返回部分成功。
- 客户端暂不自动重试 Load。提交结果不确定时停止该轮实验并报告，不重发同一批。
- COUNT、SUM、AVG 的输入包含源文件中保留的重复记录；不使用 DISTINCT 排除重复记录。
- 聚合如何处理空金额仍待确认；保留重复记录的决定不等于将空金额视为零。

## Load 接口草案

| 项目 | 当前草案 | 状态 |
| --- | --- | --- |
| HTTP 方法与类型 | POST，application/json | 待双方确认 |
| 请求体 | 现有 75 字段字符串对象数组 | 沿用现有数据契约 |
| 实验编号请求头 | X-TLQ-Run-Id | 名称、格式、长度及实验生命周期待确认 |
| 批次编号请求头 | 当前最小接口不要求 X-TLQ-Batch-Id，不用于幂等 | 如需诊断追踪，另行确认是否保留及命名 |
| 起始记录序号请求头 | 当前不要求 X-TLQ-Start-Record | 如需追踪源位置，另行确认是否保留及命名 |
| 源记录编号与表主键 | source_row_number 可供追踪；此前复合源记录标识不再作为当前最小接口要求 | 是否保留、编号约定及表主键方案待确认，不以其实现重试幂等 |
| 成功响应 | 建议 committedRecords，表示本次事务成功提交的记录数；移除 replayed | 计数含义确定，响应字段名称待确认 |
| 事务边界 | 每批独立事务，整批提交；失败整体回滚，不登记批次表 | 已确认 |

### 客户端失败处理与实验完整性

- 成功响应仅在数据库提交确认成功后返回；重复发送已成功提交的请求可能再次插入，不提供幂等保证。
- 客户端不自动重试 Load，包括 HTTP 错误、连接中断和超时；不启用隐式 POST 重试。
- 写入或提交失败且回滚确认成功时，该批没有新增已提交记录；此前其他已成功批次仍保留。
- 提交期间断线、客户端未收到成功响应等情况，可能已提交，也可能未提交；不能宣称已回滚或已写入零条。
- 遇到提交结果不确定，立即停止该轮实验并报告不确定状态，不自动重发、不继续后续批次或生成正式 Query 实验结果。
- 该轮已提交的数据不自动删除。后续检查、清理或重新实验的流程另行确认，避免将不完整实验当作完整结果。
- 错误响应格式、错误状态码及实验状态的记录方式待确认，不恢复批次登记或内容哈希机制。

## 数据类型及校验：待确认

- 金额：建议 DECIMAL，Java 使用 BigDecimal；总精度、小数位、负数、千位分隔符、超限值及额外小数位的处理待确认，不静默截断或舍入。
- 日期：严格校验真实日历日期，不自动修正不存在的日期；兼容样例中实际出现的月、日位数（1 或 2 位），不接受尾随字符。年份格式及其他可接受格式待确认。
- 空值：区分空字符串、空格、缺失字段和 JSON null；是否 trim、哪些字段映射为 SQL NULL 待确认。
- 非法日期或金额的具体校验与处理规则待确认；若判定为批次失败，遵循整批回滚，不部分提交。
- ID、邮编、NDC 保持字符串并保留前导零；Record_ID 不设置唯一约束。
- 年份、次数的数据库类型和合法范围待确认；日期暂建议 DATE。
- 字段长度需根据完整数据统计并与队友统一；暂建议 utf8mb4，排序规则、大小写比较和超长字段处理待确认，不静默截断。

## Query 接口草案

- 必须限定 run_id，隔离不同实验数据；请求参数名称及格式待确认。
- 支持按州、年份过滤，以及按州、年份或两者分组；过滤与分组字段名称、边界及空值行为待确认。
- 指标包含 COUNT、金额 SUM、金额 AVG；源文件中的重复记录均保留其贡献，不做 DISTINCT 聚合。
- COUNT 是 COUNT(*) 还是 COUNT(指定字段)，以及金额为 NULL 时 SUM/AVG 的处理，待双方确认。
- 使用参数化查询绑定过滤值，分组字段和指标只从服务端白名单映射；不拼接客户端提供的任意 SQL。
- SUM/AVG 的计算与返回精度、小数位、舍入模式、全空值或无匹配结果的表示待确认；金额结果暂建议十进制字符串。
- 响应字段名、结果排序及分页或返回数量限制待确认。

## 后续共同确认
